# Чип: задача для другой сессии и её приёмка

## Что такое чип

**Чип — одна сессия, один модуль или один подпакет.** Промт самодостаточен:
чип не задаёт вопросов и не знает истории проекта. Результат — мержабельная
ветка с кодом, тестами, `doc.go`, `CHANGELOG.md` и отчётом. Принимает арбитр.

Границы каталогов не пересекаются, поэтому шесть чипов работают параллельно и
не конфликтуют в git. Правила процесса — [CONVENTIONS §8](../CONVENTIONS.md#8-чипы-и-приёмка)
и [ADR-0005, «Процесс: чип, арбитр, приёмка»](adr/0005-packaging.md#процесс-чип-арбитр-приёмка);
этот документ даёт **шаблон промта** и **чек-лист приёмки**, а правила берёт
ссылкой.

Что чип решает сам: имена внутренних функций, состав тестов сверх названных,
разбиение по файлам. Что чип **не решает**: номер ADR, имена таблиц и
ограничений, версии общих зависимостей, состав `go.work`, строку в «Жителях» —
это выдаёт арбитр до старта либо добавляет при слиянии.

## Шаблон промта

Скопировать, заполнить `<…>`, выбросить лишние разделы. Пустой раздел хуже
отсутствующего: чип попытается его исполнить.

````markdown
## Задача

<Одно предложение: какой модуль или подпакет и что он делает.>
Ты — исполнитель-чип: одна сессия, один модуль, результат — мержабельная
ветка с тестами и CHANGELOG. Приёмка — по docs/CHIP.md, чек-лист арбитра.

## Репозиторий, ветка, worktree

- `/Users/nrect/Projects/rebar` — публичный `github.com/nrect/rebar`, MIT.
- Работай в своём worktree. В путях каталог `Projects` — **с заглавной P**:
  при строчной `projects` golangci-lint анализирует основной checkout, а не
  твою ветку, и находки указывают на чужой код.
- Ветка `<имя-ветки>` от актуального `main` (обязан содержать `<sha>`).
  Имя ветки назови в отчёте: арбитр ищет работу по имени ветки, а не по
  имени каталога worktree.
- **Не мержить в `main`, не пушить, тегов не ставить.**
- Гейты гонять с `GOWORK=off` (так их видит CI и потребитель) — это уже
  внутри `make chip-check`.
- Коммиты по-русски, по смыслу изменения.

## Правила (короткая форма; полностью — CONVENTIONS)

- модуль на пакет, `go` и `toolchain` как у соседей (VERSIONING, ADR-0005);
- ядро — stdlib (плюс названный минимум); адаптер — ядро и ровно одна
  библиотека; страж импортов с белым списком по каталогам (§1);
- порты без чужих типов: примитивы, `uuid.UUID`, `time.Time`, свои типы (§1);
- `Config` с panic-валидацией, тексты `Config.X must …`, нулевое значение —
  отказ, флагов-выключателей инвариантов нет, `SetClock` (§2);
- закрытые enum с `All*` и guard-тестом; значения в базе зеркалятся CHECK (§9);
- двойники в `<pkg>test` моделируют инвариант и не проверяют вызовы (§3);
- `<pkg>pg`: `New(pool)`, `WithTx(tx)`, `Querier`, ошибки через `Sanitize`
  (без `PgError.Detail`), `schema.sql` с goose-маркерами, префикс пакета в
  имени таблицы, без FK на таблицы потребителя, время параметром (§9, §10);
- секреты, тела и токены — ни в лог, ни в ошибку, ни в метку метрики (§2);
- комментарии коротко и по-русски: строка по умолчанию, абзац — только у
  инварианта или ловушки (§4, CLAUDE.md);
- лимиты линтера не обходить `//nolint` без причины в комментарии: `funlen`
  80 строк, `gocognit` 20, `gocyclo` 15, `nestif` 4;
- фоновая работа — `Run(ctx) (int, error)`; метрики — декоратором в
  `<pkg>otel`, meter `rebar.<pkg>` (§6, §10).

## Файлы

- Владеешь: `<модуль>/**`.
- Не трогаешь: `README.md`, `CONVENTIONS.md`, `VERSIONING.md`, `go.work`,
  `Makefile`, `.golangci.yml`, `.github/`, `scripts/`, чужие каталоги.
  Строку в «Жителях», запись в `go.work` и номер ADR добавляет арбитр:
  пять веток, дописавших туда по строке, конфликтуют между собой.

## Гейты

Первые два обязаны быть зелёными; третий пропускать нельзя — его отчёт
прикладывается к работе.

```bash
make chip-check MODULE=<модуль>
```

```bash
make lockstep
```

```bash
make mutants MODULE=<модуль> MUTANTS_EXCLUDE="-E '^<адаптер>/' -E '^doc\.go$$'"
```

**Доллар в шаблоне удваивается**, и это не опечатка: `make` съедает `$'` при
подстановке, строка обрывается на незакрытой кавычке, и `/bin/sh` падает с
`unexpected EOF`. Проверить, что дошло целиком, можно `make -n mutants …` —
он печатает команду, не запуская её.

Docker для интеграционных тестов — colima. Одного `colima start` МАЛО:
`docker ps` заработает, а testcontainers упадёт с «rootless Docker not found,
failed to create Docker provider». Он не разбирает контекст colima и ищет сокет
по умолчанию.

```bash
colima start
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock"
export TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock
```

Нужны **обе** переменные. Первая — чтобы клиент нашёл демон; вторая — для
уборщика контейнеров, который монтирует путь сокета ВНУТРИ виртуальной машины,
а не на хосте. Без второй тесты пройдут, но за собой не уберут.

Крайняя мера, если уборщик всё равно мешает: `TESTCONTAINERS_RYUK_DISABLED=true`.
Тогда контейнеры остаются висеть и снимаются руками — годится для разового
прогона, не для привычки.

Если модуль поднимает контейнеры, мутантов гонять на **общей** базе, иначе
каждый мутант поднимает свой контейнер и прогон врёт таймаутами:

```bash
TEST_DATABASE_URL=postgres://<...> make mutants MODULE=<модуль> MUTANTS_EXCLUDE="<...>"
```

### Порог: что гонится здесь, а что уходит на выделенную машину

Рабочая машина — ноутбук, и тяжёлый прогон на ней не просто долгий: он
вытесняет всё остальное и врёт таймаутами, то есть даёт неверный результат, а
не медленный. Поэтому у прогонов есть потолок.

**Здесь гонится:**

- мутанты **ядра** с исключёнными адаптерами — бюджет **десять минут** на
  модуль;
- фаззинг как дым: `-fuzztime=30s` на цель.

**Уходит на выделенную машину** (чип не гоняет, а называет команду в отчёте —
арбитр ставит её в очередь):

- любой прогон, который не уложился в десять минут;
- мутанты адаптеров: каждый мутант ходит в базу;
- длинный фаззинг — `-fuzztime` от десяти минут и выше, с накоплением корпуса.

Если прогон перевалил за потолок — **остановить и написать об этом**, а не
ждать. «Гонял час, не дождался» — это потерянный час и ноль сведений;
«остановил на десятой минуте, вот команда» — это работа, которую доделает
машина, которая для неё и заведена.

Отдельно: фаззинг **находит** вход, но доказательством становится файл в
`testdata/fuzz/<Имя>/`. Найденный вход коммитится вместе с починкой — иначе
регрессия не сторожится ничем и вернётся следующим рефакторингом.

## Отчёт

Коротко, в конце сессии:
- **имя ветки** и путь worktree;
- коммиты (`git log --oneline main..HEAD`);
- вывод `make chip-check MODULE=<модуль>` и `make lockstep`;
- отчёт gremlins: сколько мутантов, сколько выживших, где разобраны;
- отклонения от этого задания с причинами — **каждое**; неназванное
  отклонение это дефект приёмки, а не мелочь;
- вопросы арбитру, если остались.
````

## Чек-лист приёмки арбитром

Тринадцать критериев — [ADR-0005](adr/0005-packaging.md#критерии-готовности-пакета-к-тегу-v010);
здесь к каждому добавлено, чем именно проверять. Короткая форма для чипа —
[CONVENTIONS §7](../CONVENTIONS.md#7-чек-лист-нового-пакета).

| # | Критерий | Как проверять |
|---|---|---|
| 1 | `doc.go`: «Безопасность:» и «Чего в пакете НЕТ» | прочитать. У каждого пункта — причина, а не пересказ кода; каждое «нет» — решение, а не забывчивость. Пункт без названного стража — это пункт из «Чего нет» ([CORRECTNESS](CORRECTNESS.md)) |
| 2 | Страж импортов | прочитать белый список: каждый каталог назван, путь модуля берётся из `go.mod`. Проверка на срабатывание: временно добавить запрещённый импорт — тест обязан упасть |
| 3 | Порты без чужих типов | `grep -nE 'pgx\|otel\|http\\.' <модуль>/ports.go` — пусто; типы адаптеров в ядро не заезжают |
| 4 | Двойники всех портов | прочитать `<pkg>test`: моделируют ли инвариант (уникальность, аренда, идемпотентность) или запоминают вызовы; ошибки двойника отличимы; `-race` в `make chip-check` покрывает потокобезопасность |
| 5 | `Config`, `SetClock` | табличный тест на каждое обязательное поле; `grep -nE 'Skip\|Trust\|Allow' config.go` — флагов-выключателей инвариантов нет; `grep -rnE 'time\.Now' --include='*.go'` по ядру — только в конструкторе часов. **Без скобок**: правильная форма `now: time.Now` в конструкторе — значение функции, а не вызов, и `time.Now()` её не находит, то есть проверка проходила и на пакете, где часов нет вовсе |
| 6 | Закрытые enum и CHECK | есть `All*` и guard-тест «CHECK ⊇ `All*`»; значение из внешнего мира в метку не попадает |
| 7 | Тесты по именам из контрактов | `grep -rnE 'func Test.*(IsAtomic\|Race)\('`; прочитать `_IsAtomic`: читает ли он из базы **после отката**, включая строку дедупа |
| 8 | `schema.sql` | goose-маркеры и обе стороны; тест применяет на пустую базу; префикс пакета в имени таблицы, без имени схемы; имена CHECK и индексов совпадают с теми, что выдал арбитр |
| 9 | Секретов нет в логах, ошибках, метках | тест ищет подстроку секрета в тексте ошибки; `grep -rn 'Detail' <модуль>` — `PgError.Detail` наружу не уходит; `grep -rnE 'slog\\.\|log\\.' <модуль>` по адаптеру — логов в библиотеке быть не должно |
| 10 | gremlins | отчёт приложен; выжившие разобраны в `mutants_internal_test.go` — убиты или объяснены; необъяснённых ноль |
| 11 | Гейты | `make chip-check MODULE=<модуль>` и `make lockstep` в worktree чипа, своими руками, а не по отчёту |
| 12 | Метрики, CHANGELOG, «Жители» | таблица «метрика — тип — что» и пороги алертов на месте; `Unreleased` заполнен; строку в README добавляет арбитр при слиянии |
| 13 | Тег | только после того, как `examples/monolith` собирается и проходит smoke с этим модулем |

Приёмка — чтение кода плюс прогон гейтов **в worktree чипа**. Слияние —
merge-коммитом, чтобы история чипа осталась видимой.

## Типовые ошибки чипов

Всё перечисленное уже случалось. Список дороже любого списка выдуманных
рисков: это то, что проходит гейты и всплывает на приёмке или позже.

### Стражи и линтер

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Страж молчит, и это принимают за «нарушений нет» | запрет настроен, находок ноль — но ноль и должен был быть: склейка находок по строке (`issues.uniq-by-line`) оставляла одну находку на строку, и запрет проигрывал соседнему правилу | у стража обязан быть **тест на срабатывание**: корпус с заведомым нарушением, на котором находка появляется. Тест «на молчание» ничего не доказывает |
| `//nolint` без причины | лимит линтера обойдён, функция на 200 строк | лимиты — часть контракта читаемости; либо разбить, либо назвать причину в комментарии рядом |
| Тест-страж, который не может сработать НИКОГДА | «секрета нет в тексте ошибки» — зелено и на адаптере, который заворачивает `*pgconn.PgError` целиком: `Detail` в `Error()` не печатается, он достаётся через `errors.As`. Тест сторожил то, чего в тексте не бывает | проверять **тип границы**: `ErrorAs` до `*postgres.Error` с именем ограничения, `NotErrorAs` до `*pgconn.PgError`. Перед этим — доказать, что утекать есть чему: то же нарушение мимо адаптера, `require.Contains(raw.Detail, secret)`. Приём работает только поверх общего `postgres.Sanitize`: на своей копии границы `ErrorAs` не сработает, и тест будет выглядеть кривым |
| Находки линтера в файлах, которых нет на диске | `golangci-lint` красный на пути внутри снесённого worktree, рядом предупреждения «no such file or directory» | кэш линтера общий на машину и переживает каталог: `golangci-lint cache clean`. Находка не ваша и не в вашем коде |

### Git и корневые файлы

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Чип дописал строку в `go.work` | пять веток дописали по строке в один файл — конфликт при каждом слиянии | корневые файлы правит арбитр ([CONVENTIONS §8](../CONVENTIONS.md#8-чипы-и-приёмка)); чип не трогает их даже «на одну строку» |
| Утверждение про `main` без названного состояния `main` | «этих коммитов в main нет» — а они там уже полчаса: проверка сделана до чужого слияния. За день это случилось трижды, включая двух чипов, независимо назвавших себя единственными переехавшими на общий стенд | утверждая что-либо про `main`, **назвать хеш `main`, на котором проверял**: `git log --oneline -1 main`. Тогда расхождение видно сразу и разбирается за секунду, а не спором |
| Имя ветки не названо в отчёте | арбитр ищет работу по имени каталога worktree и находит не ту ветку | имя ветки — первая строка отчёта |
| Маркеры конфликта уехали в коммит | при разрешении конфликта `CHANGELOG.md` в режиме diff3 в файле остаются `<<<<<<<`, средний маркер и `>>>>>>>` | после каждого разрешения конфликта — `git diff --check`: он сообщает про оставшиеся маркеры; глазами перечитать сам `CHANGELOG.md` |

### Двойники

Все три ошибки одного рода и потому опаснее одиночных: двойник ведёт себя
как хранилище, но **не так**, как поведёт себя адаптер. Правило, из которого
они выводятся: двойник повторяет не только исходы, но и **владение данными** и
**форму вызова** — код теста и код прода обязаны отличаться одним
конструктором ([PATTERNS §7](PATTERNS.md#7-двойник-вместо-мока)).

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Двойник отдаёт наружу свою же память | в хук потребителя уходит тот же срез, что лежит внутри двойника; в адаптере на этом месте свежая строка из запроса, и правка из хука до базы не доедет, а в тесте доедет | отдавать копию: срезы и карты клонируются на выходе. Тест: изменить полученное значение и убедиться, что состояние двойника не изменилось |
| Двойник заставляет собирать композицию руками | адаптер даёт потребителю один вызов (шаг хранилища плюс доменная проверка), а на двойнике тот же сценарий пишется тремя шагами | двойник даёт функцию с той же семантикой и тем же именем. Иначе тест проверяет исход другой программы — той, что в проде не выполняется, и забытый в проде шаг тест не поймает |
| Двойник паникует там, где адаптер живёт | нулевой или отрицательный лимит выборки роняет двойник; у потребителя это выглядит как «сломался ваш пакет» | двойник обязан переживать те же пограничные аргументы, что и адаптер; на них — тест |

### Тесты

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Гонка в самом тесте | `WaitGroup`, у которого `Add` внутри горутины, или общая переменная без блокировки; `-race` мигает через раз | тест на гонку пишется так же аккуратно, как код: `Add` до `go`, общие данные под мьютексом, результат собирается каналом |
| Корпус фаззера перестал проигрываться после переименования | фаз-функцию переименовали или перенесли, каталог `testdata/fuzz/<Имя>` остался со старым именем — входы молча не проигрываются, регрессия без стража, набор зелёный | после переименования **сломать починку и убедиться, что падение приходит по имени входа** (`--- FAIL: FuzzX/df357ac1…`). Каталог обязан называться именем функции; найденный вход коммитится вместе с починкой |
| Тест на настоящих часах | ядро тестируется с `time.Now()`; baseline gremlins недетерминирован — тот же мутант то выживает, то нет | тесты ядра только на управляемых часах ([CONVENTIONS §5](../CONVENTIONS.md#5-тесты)); настоящие часы — в интеграционных тестах адаптера |

### Мутационное тестирование

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Прогон врёт зелёным | почти все мутанты `TIMED OUT`, «efficacy 100 %» при нуле выживших | `--timeout-coefficient 20` обязателен; он уже зашит в `make mutants` |
| Прогон падает не мутантом, а «failed to gather coverage» | мутируется только ядро, адаптеры исключены — а прогон всё равно требует Docker | gremlins снимает покрытие **всем набором модуля**, а не только мутируемыми пакетами: интеграционные тесты адаптера идут в любом случае. Значит `DOCKER_HOST` и `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE` нужны и тогда, когда адаптер в `-E` |
| Каждый мутант поднимает свой контейнер | прогон модуля с testcontainers идёт часами и заканчивается таймаутами | гонять на общей базе через `TEST_DATABASE_URL`; адаптеры исключать через `MUTANTS_EXCLUDE` — их держат интеграционные тесты |
| Прогон не повторили после правки ДВОЙНИКА | отчёт «264 убито, 1 выжил» остаётся верным по виду на коде, где выживших уже трое | `MUTANTS_EXCLUDE` запрещает **мутировать** файлы двойника, но не убирает двойник из прогона: мутанты ядра убиваются тестами, которые ходят через двойник, и его поведение решает, отличим мутант или нет. Правило: прогон повторяется, когда тронуто ядро **или** двойник, на котором ядро тестируется |
| Мутант неотличим через порт, потому что двойник повторил гвард домена | гвард `if limit <= 0` в сервисе и та же проверка в сторе: мутант `<` вместо `<=` проезжает в стор, оттуда приходит тот же sentinel, и тест не видит разницы | защита не ослабла — удвоилась; убивать надо утверждением о **вызове**, а не об ошибке: `require.Zero(t, store.CallCount("X"))`. Смысл гварда домена в том, чтобы не тратить круг в базу, — вот его и проверять |
| Мутант вешает тест и приходит просрочкой | мутант отключает вызов, а тест ждёт сигнала об этом вызове; набор просрочек пляшет от прогона к прогону на одном коде | лечить **порядком, а не таймаутом**: сперва утверждение о проводке, потом задержка — тогда сломанный путь падает на первом же утверждении за 0.00 с, а не висит до потолка. Потолок ожидания оставить страховкой и держать заметно ниже бюджета gremlins |
| `Killed` пляшет между прогонами на одном коде | 148 убитых и ноль просрочек в одном прогоне, 145 и три `TIMED OUT` в следующем | `Killed` не воспроизводим: он зависит от загрузки машины. Сверять по сумме **`Killed + Timed out`** и по списку `LIVED`. Каждый `TIMED OUT` разбирать руками — применить мутанта и прогнать набор; бывает, что мутант ловится паникой, путь до неё втрое длиннее, и инструмент успевает поставить просрочку раньше падения |
| Мигающий тест травит весь прогон | набор выживших пляшет от запуска к запуску на одном и том же коде (130 убитых против 84) | падающий тест убивает ВСЕХ мутантов своего прогона: сперва починить тест, потом разбирать выживших. Инвариант, который проверяется секундомером или опросом занятости, доказывается детерминированно — заполнением, а не замером |
| Выживший мутант в тексте ошибки не замечают годами | `ARITHMETIC_BASE` внутри аргумента `fmt.Errorf` живёт незамеченным, а файл разбора уверенно утверждает «выживших стабильно три» | **выражение в аргументах `fmt.Errorf` — такой же код, как в условии**, и мутанты в нём выживают ровно потому, что на текст ошибки утверждений обычно не пишут. Убивается утверждением, что сообщение называет настоящую величину; длины в тесте брать РАЗНЫЕ, иначе `+` и `−` неразличимы |
| Мутант объявлен эквивалентным без проверки | «здесь обе ветки делают то же самое» — на глаз; разбор в `mutants_internal_test.go` выглядит как работа, а на деле это списание | **сперва сформулировать ВХОД, на котором мутант ведёт себя иначе, и только не найдя такого входа, писать «эквивалентен»**. Мутант бывает и СТРОЖЕ кода: поиск маркера по всему телу вместо окна снятия типа отвергал бы законный PNG, у которого нужные байты попали в сжатые данные, — списать такого на эквивалентного особенно легко |
| Мутант в условии `case` объявлен непокрытым | `switch { case cond: }` — gremlins показывает `NOT COVERED` на заведомо покрытом условии | артефакт снятия покрытия, а не дыра в тестах; отметить в `mutants_internal_test.go` и не переписывать код под инструмент |

### Безопасность и данные

| Ошибка | Как выглядит | Что делать |
|---|---|---|
| Адрес или тело утекли через чужой текст | в лог уходит текст ответа внешнего сервера, а в нём — адрес получателя, которого мы сами не писали | логировать не чужой текст, а класс ошибки; текст внешней стороны усекать и чистить перед записью в колонку |
| Фейк провайдера мягче настоящего | фейк принимает заголовок с CR/LF, боевой API отвергает; тесты зелены, прод падает | фейк повторяет **проверки** провайдера, а не только его формат ответа |
| `PgError.Detail` в ошибке | в тексте ошибки «Failing row contains (…)» со всей строкой | `Sanitize` на границе адаптера ([CORRECTNESS §10](CORRECTNESS.md#10-секреты-и-персональные-данные)) |

## Отчёт и правки

**Чип отчитывается** в формате из шаблона: имя ветки, коммиты, вывод гейтов,
отчёт gremlins, отклонения с причинами, вопросы. Отклонение, найденное
арбитром, но не названное чипом, — дефект приёмки, а не мелочь: оно означает,
что остальной отчёт тоже нельзя читать как исчерпывающий.

**Арбитр присылает список правок** — пронумерованный, каждая с критерием, по
которому она нужна. Чип отвечает **новым коммитом в той же ветке** (не
переписывая историю: арбитр читает диффы правок отдельно от исходной работы) и
коротким ответом по пунктам: сделано / сделано иначе, потому что / не сделано,
потому что. Спорить с правкой можно и нужно, если у чипа есть довод, —
молча не делать нельзя.

**Слияние** — merge-коммитом; строку в «Жителях», `go.work`, номер ADR и тег
добавляет арбитр.
