# ADR-0001. Пакет `mail`: outbox, транспорт за портом, доставка с ретраями

Статус: **предложение, ждёт обсуждения с владельцем**. Дата: 2026-09-05.
Исследование, на котором стоит решение: [docs/research/2026-09-transactional-mail.md](../research/2026-09-transactional-mail.md).

## Контекст

В ЛайфУроке письмо уходит синхронно внутри HTTP-запроса регистрации
(`session.Register → issueVerify → SMTP`) с контекстом запроса и без ретраев.
Провайдер тормозит — тормозит регистрация; лёг — пользователь создан, клиент
получил 5xx, `register_accepted` не записан. Обёртка `BestEffort` (в работе в
основном checkout'е) закрывает 5xx и потерю аудита, но не даёт гарантии
доставки: упало — письма не будет, пока человек не попросит повторно.

Нужен переносимый пакет, дающий гарантию «операция состоялась ⇒ письмо
уйдёт», с тем же профилем безопасности, что у `payment` и `entitlement`.

## Решение в одном абзаце

Outbox в Postgres потребителя: `Enqueue` кладёт строку (в транзакции
вызывающего, если он того хочет), фоновый `Deliver` под `scheduler` забирает
пачку с арендой (`FOR UPDATE SKIP LOCKED`), шлёт через порт `Transport`,
помечает исход, повторяет по экспоненте с джиттером, после `MaxAttempts` или
постоянного отказа переводит в `failed` — видимо, с метрикой. Транспортов два:
SMTP (go-mail) и SES v2-совместимый HTTP (stdlib + своя SigV4) — второй
покрывает Yandex Cloud Postbox и настоящий SES одним кодом. Стоп-лист — порт,
необязательный; первый прод опирается на стоп-лист Postbox.

## Модель

**Message** — то, что отдаёт потребитель: `Kind`, один `To`, `Subject`,
`Text` (обязателен), `HTML`, `Headers` из белого списка, `DedupKey`,
`NotAfter`. Тексты рендерит потребитель (шаблонов в пакете нет).

**Envelope** — строка outbox: Message плюс `From` (снапшот из Config),
`Fingerprint`, `MessageID`, `Status`, `Attempts`, `NextAttemptAt`,
`LockedUntil`, `LastError`, `FailReason`, `Transport`, `ProviderMessageID`,
времена.

**Статусы** (закрытый набор, CHECK в схеме):
`pending → sending → sent | failed | expired | suppressed`, `sending → pending`
на временном сбое. Терминальные — sent/failed/expired/suppressed; в них тело
стёрто.

## Идемпотентность (приём из `payment`)

- `dedup_key` — глобальный `UNIQUE`; нормализуется одной функцией
  `NormalizeKey` (перенесена из payment без изменений — кандидат в общий
  пакет при переезде payment).
- `fingerprint` — sha256 с префиксами длины по (kind, to, subject, text,
  html, отсортированные headers). From и NotAfter не входят: смена конфига и
  секунды между попытками не должны превращать повтор в конфликт.
- Тот же ключ + тот же отпечаток → `OutcomeDuplicate`, существующая строка,
  **успех**. Тот же ключ + другой отпечаток → `ErrKeyReused`, громко. Пустой
  сохранённый отпечаток — не повтор (страховка от адаптера, потерявшего
  колонку).
- Потребитель выводит ключ из факта: `verify:` + sha256(rawToken),
  `reset:` + sha256(rawToken), `existing:<email>:<час>` (уведомление на занятый
  адрес — не чаще раза в час, и это тоже анти-энумерация: перебор регистраций
  не превращается в бомбёжку чужого ящика).

## «В той же транзакции»

Ядро транзакций не знает. Контракт: строка outbox вставляется в транзакции
бизнес-факта, и это доказывается интеграционным тестом адаптера потребителя,
как `paymentpg.TestStore_ApplyEvent_IsAtomic`.

Механика — два пути через одну проверку:

```go
// Путь 1: без транзакции (достаточно для писем аутентификации, см. ниже).
res, err := mailSvc.Enqueue(ctx, msg)

// Путь 2: в транзакции потребителя.
env, err := mailSvc.Prepare(msg)             // чистая валидация и отпечаток
res, err := mailStore.WithTx(tx).Enqueue(ctx, env)  // адаптер, та же tx
```

`Prepare` чистый (ни хранилища, ни времени внешнего мира) именно ради второго
пути. Оба пути проходят одну валидацию, потому что она в одном месте.

Для ЛайфУрока путь 1 на первом шаге честен: `CreateVerifyToken` и `Enqueue` —
два запроса в одну базу, окно отказа между ними — падение самой базы, и оно
одинаково ломает оба. Путь 2 нужен там, где письмо — следствие денег
(чек по `ApplyEvent`): адаптер `paymentpg` вставит конверт в ту же транзакцию.

## Доставка

`Deliver(ctx) (processed int, err error)` — сигнатура `scheduler.Job.Run`:

1. `Claim(now, Lease, BatchSize)`: pending с `next_attempt_at <= now` и
   sending с истёкшей арендой; `FOR UPDATE SKIP LOCKED`; переводит в sending,
   `attempts += 1`.
2. Для каждой строки, с паузой `MinSendGap` между письмами:
   - `NotAfter` наступил → `FinishExpired`;
   - строка пришла с истёкшей арендой (Attempts > 1 при том же LastError) и
     `Uncertain = Park` → `FinishFailed(uncertain)`;
   - `Suppressor.IsSuppressed`: ошибка → `FinishRetry` (не слать, раз не
     проверили), в списке → `FinishSuppressed`;
   - `Transport.Send` с `context.WithTimeout(SendTimeout)`;
   - успех → `FinishSent(transport, providerMessageID)`;
   - `RejectedError` → `FinishFailed(rejected)`;
   - иначе `Attempts >= MaxAttempts` → `FinishFailed(exhausted)`, иначе
     `FinishRetry(now + Backoff.delay(attempts))`.
3. Сбой отдельной строки — исход строки, не прогона: `Deliver` возвращает
   ошибку только на сбое `Claim` (иначе одна вечно ломающаяся строка морозила
   бы гейдж последнего успеха, и «крон умер» горел бы при живом кроне — тот
   же урок, что у `payments_reconcile`).

`Purge(ctx)` — вторая задача планировщика: удаляет терминальные строки старше
`Retention`, пачками.

**At-least-once сказан вслух** (doc.go, п. 5): падение между `Send` и `Finish`
даёт второе письмо после истечения аренды. Инварианты, сужающие окно: `Lease >
SendTimeout` (валидируется), детерминированный `Message-ID` (помогает в
SMTP-пути; SES-совместимые API его перезаписывают — это записано в sesv2),
политика `Uncertain`.

## Fail-closed для почты — что это значит

| Ситуация | Fail-open (как сейчас) | Fail-closed (пакет) |
|---|---|---|
| Транспорт не настроен в проде | `LoggingMailer`, токены в логах | `NewService` паникует на nil; конфиг потребителя обязан отказать старту без транспорта в production (как `PAYMENT_PROVIDER=stub`) |
| SMTP-клиент не собрался на старте | лог + `LoggingMailer` | паника на старте |
| Стоп-лист недоступен | — | письмо не уходит, повтор позже |
| Провайдер отказал определённо | — | `failed`, без ретраев, метрика |
| Неизвестный Kind | — | `ErrBadKind` на Enqueue |
| Срок ссылки истёк до отправки | письмо уйдёт | `expired`, не уйдёт |
| CR/LF в теме или имени | зависит от библиотеки | `ErrInvalidMessage` до записи |
| Тело письма в БД после отправки | — | стёрто в терминальном статусе; строки удалены после Retention |

## Транспорты

**smtp** — перенос `internal/common/mail` из ЛайфУрока на go-mail v0.8.1 с
двумя изменениями: TLS по умолчанию mandatory, `none` — только явным
`AllowPlaintext` (для Mailpit в docker); ответ на `DATA` парсится на queue id
как `ProviderMessageID`, если сервер его назвал. Постоянные отказы — SMTP 5xx
на RCPT/DATA → `RejectedError`; 4xx и сетевые — временные.

**sesv2** — `POST {endpoint}/v2/email/outbound-emails`, Simple-контент
(Subject/Text/Html + Headers), SigV4 на stdlib (`crypto/hmac`, `sha256`;
~100 строк). Конфиг: endpoint, region, service (`ses`), access key id +
secret. Postbox: `https://postbox.cloud.yandex.net`, `ru-central1`; AWS:
`https://email.<region>.amazonaws.com`. Ошибки: 400 `MessageRejected`,
`BadRequestException`, `MailFromDomainNotVerifiedException`,
`AccountSuspendedException` → `RejectedError`; 429, 5xx, сеть → временные;
`SendingPausedException` — временный (это «пауза», не «нет»); любой 403 —
временный (ошибка нашей конфигурации, не письма, и алерт по `result="error"`
её покажет). Реализация 2026-09-05 уточнила два места против этого текста:
`Message-ID` провайдеру НЕ передаётся вовсе — и SES, и Postbox отвергают его
в `Content.Simple.Headers` (400), так что дедуп клиентом в этом транспорте не
работает, как и предполагалось; `Reply-To` из белого списка уходит полем
`ReplyToAddresses`, а не заголовком.

**mailotel** — декоратор `Transport`: `emails_sent_total{type,result}` с
`result = ok | rejected | error` (как `paymentmetered`: сведи rejected и error
— алерт «провайдер недоступен» горит от фонового шума) и
`RegisterGauges(meterProvider, svc)`: `email_outbox_pending`,
`email_outbox_oldest_pending_age_seconds`, `email_outbox_failed`. Гейджи
читают `Stats()` под коллбэком с таймаутом 2 с — как `registerCountGauge` в
ЛайфУроке; запросы дешёвые (частичный индекс по статусу).

## Двойники (`mailtest`)

- `MemStore` — потокобезопасный `Store` с настоящей уникальностью ключа,
  арендой и SKIP-LOCKED-семантикой (строка в sending с живой арендой не
  выдаётся); `Err` для fail-closed тестов; `Calls`.
- `Transport` — записывает конверты; `RejectFor[email]`, `FailFor[email]`,
  `FailTimes` для сценариев ретраев; `Sent()` для проверки «ровно один раз».
- `MemSuppressor` — карта + `Err`.
- `SESServer` — `httptest.Server` с SES v2 endpoint: проверяет форму SigV4,
  хранит письма, отдаёт `MessageId`, имитирует `MessageRejected`/429 по
  адресу; на нём тестируется адаптер `sesv2` без Docker.
- `cmd/sesfake` — тот же сервер как бинарь для стенда, с релеем в SMTP
  (Mailpit) и веб-списком принятого.

## Наблюдаемость и алерты (для таблиц потребителя)

| Метрика | Тип | Что |
|---|---|---|
| `emails_sent_total{type,result}` | counter | результат каждой попытки транспорта; семантика меняется: считается в воркере, а не в HTTP-запросе |
| `email_outbox_pending` | gauge | строк в pending/sending |
| `email_outbox_oldest_pending_age_seconds` | gauge | возраст самой старой неотправленной; ловит «воркер жив, ничего не уходит» |
| `email_outbox_failed` | gauge | терминальных отказов до Purge |
| `cron_*{job="mail_deliver"}`, `{job="mail_purge"}` | из scheduler | прогоны, длительность, последний успех |

Алерты: «почта застряла» — `oldest_pending_age > 600` 10 мин (page);
«письма умирают» — `increase(email_outbox_failed[1h]) > 0` (порог 1, разбор
по audit `email_failed` с kind, усечённым адресом, причиной — без тела);
«провайдер отказывает» — `rate(emails_sent_total{result="rejected"})` доля
> 5 %; «крон почты умер» — `time() - cron_last_success{job="mail_deliver"} >
180` при интервале 30 с.

## Стоп-лист

Порт `Suppressor` с `IsSuppressed` / `Suppress`. Первый прод: `nil` —
стоп-лист Postbox автоматический и общий на облако, отказ на отправку
приходит как `MessageRejected` → `failed(rejected)` → метрика. Второй этап
(если появятся вебхуки — Unisender Go — или ручное управление): таблица
`email_suppressions` в `mailpg`, HTTP-ручка вебхука в потребителе под
отдельным префиксом `/api/v1/webhooks/mail` (по правилу PAYMENTS.md: вебхуки
не соседи пользовательского API), адаптер провайдера переводит JSON в
`Suppression`.

## Схема (`mailpg/schema.sql`, goose)

```sql
CREATE TABLE email_outbox (
    id                  UUID PRIMARY KEY,
    kind                TEXT NOT NULL,
    to_email            TEXT NOT NULL,
    to_name             TEXT NOT NULL DEFAULT '',
    from_email          TEXT NOT NULL,
    from_name           TEXT NOT NULL DEFAULT '',
    subject             TEXT NOT NULL,
    body_text           TEXT NOT NULL,
    body_html           TEXT NOT NULL DEFAULT '',
    headers             JSONB NOT NULL DEFAULT '{}'::jsonb,
    dedup_key           TEXT NOT NULL,
    fingerprint         BYTEA NOT NULL,
    message_id          TEXT NOT NULL,
    status              TEXT NOT NULL CHECK (status IN ('pending','sending','sent','failed','expired','suppressed')),
    attempts            INT NOT NULL DEFAULT 0 CHECK (attempts >= 0),
    next_attempt_at     TIMESTAMPTZ NOT NULL,
    locked_until        TIMESTAMPTZ,
    last_error          TEXT NOT NULL DEFAULT '',
    fail_reason         TEXT NOT NULL DEFAULT '' CHECK (fail_reason IN ('', 'rejected','exhausted','uncertain')),
    transport           TEXT NOT NULL DEFAULT '',
    provider_message_id TEXT NOT NULL DEFAULT '',
    not_after           TIMESTAMPTZ,
    created_at          TIMESTAMPTZ NOT NULL,
    updated_at          TIMESTAMPTZ NOT NULL,
    sent_at             TIMESTAMPTZ,
    -- тело стёрто в терминальном статусе: контракт Store.Finish
    CONSTRAINT email_outbox_body_cleared_chk CHECK (
        status IN ('pending','sending') OR (subject = '' AND body_text = '' AND body_html = '')
    ),
    CONSTRAINT email_outbox_lock_chk CHECK ((status = 'sending') = (locked_until IS NOT NULL))
);
CREATE UNIQUE INDEX ux_email_outbox_dedup ON email_outbox (dedup_key);   -- имя — часть контракта Store.Enqueue
CREATE INDEX ix_email_outbox_due ON email_outbox (next_attempt_at, id) WHERE status IN ('pending','sending');
CREATE INDEX ix_email_outbox_terminal ON email_outbox (updated_at) WHERE status IN ('sent','failed','expired','suppressed');
```

Kind без CHECK: набор задаёт потребитель; проверяет `Prepare`. Схема
копируется в `migration/` потребителя как есть — так же, как копируется
каталог пакета.

## Что остаётся решить с владельцем

1. ~~Имя репозитория и модуля.~~ Решено 2026-09-05: `rebar` (арматура), личный аккаунт, `github.com/nrect/rebar/mail`, репозиторий публичный.
2. **Модуль на пакет** (`mail/go.mod`, теги `mail/v0.1.0`) против одного модуля на репозиторий. Предложено — на пакет, причины в VERSIONING.md.
3. **`Prepare` + `WithTx` как способ вставки в транзакции** против варианта «транзакция в ctx». Предложено явное `WithTx`: магии нет, контракт виден в коде.
4. **Один получатель на письмо** — жёсткий запрет Cc/Bcc в порту. Есть ли у будущих проектов письма с копией (бухгалтерия)? Если да — это отдельное поле с отдельным правилом, а не список To.
5. **Тело стирается в терминальном статусе** — теряем возможность «показать, что именно ушло» в админке. Альтернатива — шифровать тело ключом потребителя; дороже и пока без потребителя.
6. **`Uncertain` — глобальная политика или на Kind?** Предложено глобальная; чекам дадут отдельный Kind и отдельный сервис, если понадобится Park.
7. **Провайдер прода — Postbox** (0 ₽ сейчас, без вебхуков) против Unisender Go (800 ₽/мес, с вебхуками). Предложено Postbox; стоп-лист — их.
8. **sesfake свой** против aws-ses-v2-local. Предложено свой (см. исследование §6).
9. Что делать с `LoggingMailer` в dev: предложено убрать — Mailpit поднимается `make local-mail`, а outbox без транспорта честно копит строки и показывает это в гейдже.
10. **Прод без провайдера.** В ЛайфУроке прод поднимается раньше, чем заведена почта (коммит 7b00eba в dev: вне development пустой `SMTP_HOST` даёт `mailer.NotConfigured` — отказ без логов, через `Metered` и `BestEffort`). Значит «nil-транспорт = паника на старте» для такого потребителя не подходит. Предложение: транспорт `mail.Unconfigured` в ядре — `Send` всегда возвращает временный сбой, строки копятся в outbox с backoff, и когда провайдер появится, они уйдут сами (в пределах `MaxAttempts` и `NotAfter`). Письма аутентификации при этом протухнут по `NotAfter`, но чеки дождутся. Гейдж `email_outbox_oldest_pending_age_seconds` показывает состояние честно.

## Последствия

Плюсы: регистрация не зависит от провайдера ни по времени, ни по
доступности; тайминг ответа перестаёт выдавать занятость адреса; письмо
переживает падение провайдера и рестарт; один HTTP-адаптер на Postbox и AWS
SES; `emails_sent_total` считает то, что действительно ушло.

Минусы, принятые осознанно: at-least-once с известным окном; таблица и два
крона в каждом потребителе; письма уходят с задержкой до интервала
`mail_deliver` (30 с) — для ссылки подтверждения это незаметно, для кода из
SMS было бы нет (SMS здесь нет); `BestEffort` становится лишним слоем и
удаляется на шаге миграции.
