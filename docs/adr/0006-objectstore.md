# ADR-0006. Файлы пользователей: порт хранилища, загрузчик, сборщик сирот

Статус: **принято** 2026-09-09 — карта модулей v0.1 (`objectstore` нужен
каталогу товаров: десять тысяч позиций означают десятки тысяч картинок).
Форма пакета — [ADR-0001](0001-mail.md); упаковка и приёмка —
[ADR-0005](0005-packaging.md); законы данных — [CORRECTNESS](../CORRECTNESS.md).

## Контекст

Каждый проект заводит свою работу с файлами заново: где-то `multipart` пишется
прямо в обработчик, где-то ключ объекта собирается из имени файла, которое
прислал пользователь, где-то удаление строки в базе не удаляет объект и хранилище
растёт молча. Ошибки повторяются, потому что повторяется код.

Опасность здесь не в сложности, а в том, что **все три типичные дыры выглядят
как мелочь**: имя файла в ключе (обход каталога и утечка исходного имени),
доверие заголовку `Content-Type` (SVG со скриптом отдаётся с нашего домена),
чтение тела до проверки размера (память кончается раньше, чем сработает лимит).

## Решение в одном абзаце

Порт `Store` — пять методов над «положить, удалить, перечислить, подписать
ссылку». Над ним `Uploader`, который решает ЕДИНСТВЕННЫЙ вопрос «можно ли это
принять», и `Collector`, который убирает объекты, потерявшие владельца.
Адаптеры: `s3` на stdlib (SigV4 своими руками, как в `mail/sesv2`), `fs` для
разработки, `imgproxy` — подписанные ссылки на преобразование. Ресайза в
процессе нет, `multipart` нет, публичных бакетов по умолчанию нет.

## Порты

```go
type Store interface {
    Put(ctx context.Context, req PutRequest) (Object, error)
    Delete(ctx context.Context, key string) error
    List(ctx context.Context, prefix, cursor string, limit int) (Page, error)
    Presign(ctx context.Context, key string, method Method, ttl time.Duration) (string, error)
    PublicURL(key string) string
}

type PutRequest struct {
    Key         string
    ContentType string
    Body        io.Reader
    Size        int64   // -1 — размер неизвестен, потолок держит Uploader
}
```

`Method` — закрытый набор (`MethodGet`, `MethodPut`), зеркалится проверкой
адаптера. `Page` несёт `Objects` и `Cursor`; пустой курсор — конец.

## Инварианты загрузчика

1. **ПОТОЛОК РАЗМЕРА ДЕЙСТВУЕТ ДО ЧТЕНИЯ, А НЕ ПОСЛЕ.** Тело оборачивается
   `io.LimitReader(body, MaxSize+1)`; превышение узнаётся по лишнему байту.
   Проверка после чтения — это проверка после того, как память уже занята.
2. **ТИП ОПРЕДЕЛЯЕТСЯ ПО СОДЕРЖИМОМУ**, `http.DetectContentType` по первым 512
   байтам, а заголовок запроса — лишь подсказка. Заголовок пишет клиент, и
   доверять ему значит принимать имя за суть.
3. **SVG ОТВЕРГАЕТСЯ ВСЕГДА.** Это документ со скриптами, а не картинка: отдав
   его со своего домена, мы отдаём чужой JS в своей origin. Исключений нет —
   поэтому это не поле конфигурации.
4. **КЛЮЧ СТРОИМ МЫ.** `<prefix>/<uuid>.<ext>`, расширение — из белого списка по
   определённому типу. Имя файла пользователя в ключ не попадает никогда: в нём
   бывают `../`, символы, ломающие подпись, и персональные данные.
5. **ИМЯ ФАЙЛА ПОЛЬЗОВАТЕЛЯ — ДАННЫЕ, А НЕ ПУТЬ.** Хочет потребитель показывать
   исходное имя — хранит его у себя в колонке.

## Сборщик сирот

`Collector` сверяет ключи хранилища со списком владельцев потребителя (порт
`Owned{IsOwned(ctx, key) (bool, error)}`) и удаляет то, что не принадлежит
никому. Два предохранителя, оба обязательны:

- **grace-период**: объект моложе `MinAge` не трогается никогда. Между `Put` и
  вставкой строки потребителя есть окно, и без grace сборщик удалял бы файлы,
  которые прямо сейчас загружают;
- **`DryRun`**: первый прогон у нового потребителя только считает. Сборщик,
  который начинает с удаления, ошибку в `IsOwned` показывает уже потерянными
  файлами.

Сбой `IsOwned` — остановка прогона, а не «считаем сиротой»: недоступная база
означала бы, что сиротами признаются все.

## Адаптеры

| Адаптер | Библиотека | Зачем |
|---|---|---|
| `s3` | нет, stdlib | SigV4 подписывается своими руками — приём уже есть в `mail/sesv2`. `PathStyle` обязателен: Yandex, VK и MinIO работают так |
| `fs` | нет, stdlib | разработка без контейнера; `Presign` отдаёт локальный URL, `PublicURL` — путь |
| `imgproxy` | нет, stdlib | подписанная HMAC ссылка на преобразование; сам imgproxy — отдельный контейнер, не библиотека |

**Копия SigV4 — осознанная.** ADR-0005 разрешает межмодульные зависимости
только на `kit`, `postgres` и `postgres/pgtest`; `mail/sesv2` в этот список не
входит, и тянуть весь модуль почты ради подписи нельзя. Это второй потребитель
приёма — по правилу «копируемые мелочи не выносятся до третьего» копия
законна, но записывается в долги.

## Чего нет (решения, не пробелы)

- **ресайза и обработки картинок в процессе**: `govips`/`bimg` тянут C-библиотеку
  и делают из веб-процесса обработчик изображений; преобразование — задача
  `imgproxy` как отдельного контейнера, мы лишь подписываем ссылку;
- **`multipart`-загрузки**: она нужна файлам от сотен мегабайт, а у каталога их
  нет. Появится потребность — появится метод, ломать порт не придётся;
- **публичных бакетов по умолчанию** и `PutBucketPolicy`: права бакета — работа
  инфраструктуры, а пакет, умеющий открыть бакет миру, однажды его откроет;
- **своего кэша и CDN**: то и другое живёт перед приложением;
- **вирусного сканирования**: это отдельный сервис и отдельное решение;
- **удаления по расписанию без владельца**: без порта `Owned` сборщик — это
  `rm -rf` с таймером.

## Последствия

Потребитель получает загрузку, у которой три типичные дыры закрыты не
дисциплиной, а конструкцией, и сборщик, который нельзя случайно натравить на
живые файлы. Цена — своя реализация SigV4 (вторая копия в тулките) и то, что
преобразование картинок требует поднятого `imgproxy`.
