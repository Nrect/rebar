# ledger — журнал движений остатка, который приложение не может переписать

Кошелёк, баллы, возврат на счёт: остаток покупателя вместе с обоснованием.
Запись неизменяема, номер в счёте без дыр, остаток после движения лежит в самой
записи, каждая запись подписана HMAC цепочкой с ключом вне базы, отмена —
встречной записью. Сверка по расписанию проверяет всё это на живых данных и
поднимает алерт. Решения и доводы — [ADR-0009](../docs/adr/0009-ledger.md).

Состояние: ядро, двойник с контрактным набором, адаптер `ledgerpg`, сверка и
метрика `ledgerotel`. Тегом не выпущен.

## Когда брать

- остаток живёт у проекта: предоплата, возврат на счёт, баллы;
- на вопрос «почему у него столько» нужен ответ записями, а правка остатка
  мимо журнала должна быть видна.

## Когда не брать

- **деньги у провайдера по схеме «карта → заказ»** — это `payment`;
- **несколько валют в одной книге, перевод между книгами** — единица —
  свойство книги, курс предметен;
- **начисления по расписанию, сгорание, квоты** — политика проекта поверх
  `Post`, а не журнал.

## Как подключить

Пример целиком — [example_test.go](example_test.go), он собирается и
проверяется `go test`.

1. **Книга и ключ.** `ledger.Config{Book: wallet, Keys: {1: key}, ActiveKey: 1}`,
   ключ — `secrets.DeriveKey(секрет, wallet.Name)`. Новый ключ — новый номер;
   старый из `Keys` не удаляется никогда.
2. **Схема.** `ledgerpg.Migrations()` накатывает раннер проекта с таблицей
   версий `ledger_schema_version`; справочники `ledger_books` и `ledger_kinds`
   пишет миграция проекта из `Config`; права роли приложения — рецепт в
   [ledgerpg/doc.go](ledgerpg/doc.go). На старте — `store.CheckSchema(ctx)`.
3. **Движение — в транзакции бизнес-факта:**
   `svc.WithStore(store.WithTx(tx)).Post(ctx, req)`. Отказ движения
   (`ErrInsufficientFunds`) транзакцию не рвёт: проект разбирает его и
   продолжает.
4. **Сверка — задача планировщика рядом с движениями.** Сервис сверки — на
   пуле, без `WithStore`: транзакция потребителя ей не нужна.

```go
store := ledgerpg.New(pool, wallet)
svc := ledger.NewService(store, walletCfg)

obs, err := ledgerotel.NewObserver(meter) // проект без метрик: ledger.LogObserver(logger)
if err != nil {
	return err
}
rec := ledger.NewReconciler(svc, obs, ledger.ReconcileConfig{
	Accounts: 200, // счетов за прогон: длину прогона задаёт он
	Page:     500, // записей за чтение: память на счёт с длинной историей
})
jobs, err := scheduler.New(cronObs,
	scheduler.Job{Name: "wallet_reconcile", Interval: 10 * time.Minute, Run: rec.Run},
)
```

Прогон проверяет порцию счетов и отдаёт число проверенных записей; за круг
обход доходит до каждого счёта, после последнего — с начала. Курсор в памяти:
перезапуск процесса начинает с начала книги, и ничего не теряется.

## Что нельзя ломать

- **Ключ подписи не удаляется из `Config`.** Без него записи не проверить:
  сверка горит `unknown_key` на каждом проходе.
- **Роль приложения — не владелец схемы.** Владелец снимает уровень привилегий,
  и остаток правится мимо журнала без единой ошибки.
- **Наблюдатель сверки подключён, алерт настроен.** Подпись без сверки — сторож,
  который молчит: ровно из-за этого сверка стала условием выпуска.
- **После `pg_restore --disable-triggers` — повторный накат миграций.**
  `pg_restore` возвращает триггеры режимом `ENABLE`, а не `ALWAYS`, и
  `CheckSchema` назовёт каждый; правку данных в окне восстановления видит
  только сверка.

## Ошибки

| Ошибка | Класс | Когда |
|---|---|---|
| `ErrKeyReused` | 409 | тот же ключ идемпотентности на другую операцию |
| `ErrInsufficientFunds` | 409 | остаток ушёл бы ниже `Book.Floor` |
| `ErrNotReversible`, `ErrAlreadyReversed` | 409 | род не разрешает отмену, запись — отмена или уже отменена |
| `ErrEntryNotFound` | 404 | отменяемой записи нет на этом счёте |
| `ErrUnavailable` | 503 | хранилище не ответило или проиграна гонка номера: повтор осмыслен |
| `ErrInvalidRequest`, `ErrInvalidKey`, `ErrUnknownKind` | нет | класс решает вызывающий: ввод клиента или дефект кода |

## Тесты

`ledgertest.NewMemStore(book)` ведёт себя как адаптер: номер, цепь, остаток,
граница, ключ, одна отмена, моменты как в `timestamptz`, обход счетов,
`SetErr` и отмена в `ErrUnavailable`. Код теста отличается от прода
конструктором хранилища. `ledgertest.Observer` запоминает находки сверки;
`ledgertest.RunStoreSuite` — контрактный набор для своего хранилища.

## Наблюдаемость

`ledgerotel`: счётчик `ledger_reconcile_mismatch{book,check}`, ряды рождаются
нулём при сборке сверки. Алерты — «журнал правили мимо пакета» и «ключ подписи
удалён» с порогом 1, «сверка умерла» — по `cron_last_success_timestamp_seconds`
задачи. Таблица и тексты — [ledgerotel/doc.go](ledgerotel/doc.go).

Инварианты и «Чего нет» — [doc.go](doc.go); изменения — [CHANGELOG.md](CHANGELOG.md).
