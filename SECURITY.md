# Безопасность

## Как чинится уязвимость

1. Исправление в этом репозитории, в пакете; тест, который падал бы до
   исправления; запись в `<pkg>/CHANGELOG.md` под `Security`.
2. Тег `<pkg>/vX.Y.Z` (патч, если контракт не менялся).
3. В каждом проекте-потребителе — `go get github.com/nrect/rebar/<pkg>@vX.Y.Z`,
   `make ci`, выкат. Список потребителей — в README пакета.

Пакеты, скопированные каталогом, обновляются руками: это единственная причина
предпочитать модульное подключение.

## Что сканируется

- `govulncheck` на каждом PR и еженедельно по `main`
  (`.github/workflows/vuln-scan.yml`): CVE появляются без наших пушей.
- `gosec` в составе golangci-lint.
- gitleaks — джоб CI `secrets` по рабочему дереву (`make secrets` локально) и
  pre-commit хук по индексу (`make hooks`), оба с `.gitleaks.toml`. Хук стоит
  не у всех, поэтому страж — CI. Исключения в `.gitleaks.toml` — только точные
  тестовые значения: исключение по пути gitleaks применяет ко всему файлу, и
  настоящий токен в `_test.go` прошёл бы.

## Цепочка поставки

Код, который исполняется в CI, — такой же вход в репозиторий, как зависимость
модуля.

- **Действия — по полному SHA коммита** с версией в комментарии:
  `actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0`. Тег
  действия владелец перевешивает на любой коммит, и сборка молча исполняет
  чужой код с токеном репозитория — так в 2025 году подменили
  `tj-actions/changed-files`. Dependabot (`github-actions` в
  `.github/dependabot.yml`) обновляет SHA вместе с комментарием.
- **Образы — по digest**: `postgres:16-alpine@sha256:…` в `pgtest` и стенде,
  образ gitleaks в CI.
- **У каждого джоба `permissions:`** не шире `contents: read`: токен по
  умолчанию может писать в репозиторий.
- **Пути не различаются одним регистром**: на macOS два таких файла — один, на
  Linux — два, и сборка разъезжается между машинами.

Страж — `scripts/ciguard.sh` (джоб CI `guards`, `make ciguard`, шаг
`make chip-check`), исключений у него нет. Те же правила для проекта —
[CONSUMER §9](docs/CONSUMER.md#9-сеть-база-и-json).

## Что не хранится

Никаких ключей провайдеров, DSN, паролей в репозитории — даже тестовых.
Интеграционные тесты поднимают контейнеры сами (testcontainers) и пользуются
одноразовыми кредами.
